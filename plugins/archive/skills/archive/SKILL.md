# 사례 아카이브 — 건축 사례 찾기

사례 아카이브 커넥터 도구로 회사 비공개 건축 사례 아카이브(dailyarchive.heeai.cloud)를 검색한다. 아카이브 웹 화면과 같은 검색·같은 북마크·같은 컬렉션을 쓴다. 요청: $ARGUMENTS

**답은 사용자가 이번 요청을 쓴 언어로 한다.** 이 안내문과 도구 메시지가 한국어여도 영어로 물으면 영어로 답한다.

## 1. 연결 확인
- 사례 아카이브 도구(`search_cases`, `get_case` …)가 안 보이면 연결부터 안내한다. 커넥터 주소는 `https://dailyarchive.heeai.cloud/mcp`이고, 연결할 때 heeai.cloud 로그인 화면(희림 아이디, 사내 도구 대문과 같은 아이디)이 뜬다. 이미 대문에 로그인된 브라우저면 «연결» 확인 화면만 나온다.
  - Claude Code: `/mcp` → archive → Authenticate.
  - claude.ai·Cowork: 플러그인의 **커넥터(Connectors)** 탭에서 archive «연결».
  - ChatGPT 앱(데스크톱): 설정 → 플러그인 → archive에서 희림 아이디로 로그인한다. 도구는 이 컴퓨터에서 도는 대화(«작업 위치» = «이 컴퓨터»·로컬에서 작업)에만 붙는다. 일반 채팅이나 «클라우드에서 작업»으로 도는 대화라서 도구가 안 보이면, 연결을 다시 하라고 하지 말고 새 대화의 «작업 위치»를 «이 컴퓨터»로 바꿔 다시 부탁하라고 안내한다. Windows용 앱은 로그인한 뒤에도 연결이 안 될 수 있다(앱 쪽 문제).
  - 회사 조직 계정으로 쓰는데 «연결»이 눌리지 않으면 조직 관리자(Owner)가 먼저 **조직 설정 → 커넥터(Organization settings → Connectors)**에서 `https://dailyarchive.heeai.cloud/mcp`를 커스텀 커넥터로 추가해야 한다. OAuth 클라이언트는 Claude가 찾은 «자동으로 등록» 그대로 둔다.
  - 설치 안내: https://dailyarchive.heeai.cloud/claude/ (희림 아이디로 로그인해서 연다)
- 도구가 «unauthorized»·401로 실패하면 연결이 풀린 것이다(heeai.cloud 비밀번호를 바꿨거나 관리자가 로그아웃시킨 경우). 같은 방법으로 다시 연결하라고 안내한다.

## 2. 찾기
- 요청이 비어 있으면(`/archive`만 입력) 무엇을 찾을지 고르게 한다.
  - 보기 창이 뜨는 앱(claude.ai 채팅·Cowork): `archive_home`을 부른다. 검색창·예시·«사진으로 찾기»·«내 북마크·컬렉션»이 있는 첫 화면이 뜨고 사용자는 그 안에서 바로 찾는다. 보기 창에서 찾은 결과는 대화 맥락으로 들어온다. 답은 «아래에서 찾거나 바로 물어보세요» 한 줄만 쓴다.
  - Claude Code(터미널, 데스크톱 Code 탭): 보기 창이 안 보이므로 도구를 부르지 않고 AskUserQuestion 질문 하나로 고르게 한다. 선택지는 넷이다. 사례 찾기(«목조 도서관 사례 찾아 줘»), 조건 붙여 찾기(«일본 중정형 공동주택, 2015년 이후»), 사진으로 찾기(사진 파일을 주고 «이 사진이랑 비슷한 사례»), 내 북마크·컬렉션. 고르면 찾을 말이나 사진 파일 경로를 묻고 진행한다. AskUserQuestion을 쓸 수 없으면 같은 넷을 짧은 목록으로 보여 주고 묻는다.
  - ChatGPT 앱(데스크톱): 보기 창이 뜨지 않고 AskUserQuestion도 없다. 도구를 부르지 않고 Claude Code와 같은 선택지를 번호 목록으로 보여 준 다음 사용자의 답을 기다린다.
  - 어느 쪽인지 모르겠으면 `archive_home`을 부르고 결과의 `for_claude`를 따른다.
  - 자세한 사용법은 https://dailyarchive.heeai.cloud/claude/usage (희림 아이디로 로그인해서 연다).
- `search_cases`: query에는 사용자가 쓴 말을 그대로 넣는다(한국어·영어 모두 된다). 유형·국가·재료·연도·면적 조건이 분명하면 필터로도 넣는다. 필터 값이 헷갈리면 `list_case_filters`로 정확한 값을 먼저 본다(유형·재료는 한국어, 국가는 영어 이름).
  - `status: searching`이면 아카이브가 처음 보는 검색어를 푸는 중이다. 사용자에게 찾는 중이라고 한 줄 알리고 같은 검색을 그대로 다시 부른다.
  - 결과는 12건씩 온다. 더 필요하면 `next_offset`을 offset에 넣는다.
  - 사진 카드 보기 창이 뜨는 앱(claude.ai·Cowork)에서는 카드에 사진·이름·건축가·위치·연도가 다 나온다. 글로 모든 사례를 다시 늘어놓지 말고, 요청에 잘 맞는 몇 개를 골라 왜 맞는지 짧게 말한다.
  - 0건이면 검색어를 넓히거나 조건을 하나 빼고 한 번 더 찾는다.
- `get_case`: 한 사례의 사실·요약·갤러리를 본다. 대표 사진이 같이 오니 사진에서 보이는 것(외장 재료·매스·구조)도 설명할 수 있다. 사진에서 본 것과 기록된 사실은 구분해서 말한다.
- `similar_cases`: 외관 사진과 매스가 비슷한 사례를 찾는다.
- 여러 사례 비교(«이 세 개 비교해 줘»): 각각 `get_case`로 사실을 모아 표로 정리한다. 기록에 없는 값(연도·면적 등)은 빈칸으로 두고 채우지 않는다.

## 3. 사진으로 찾기
- 사용자가 사진을 주고 비슷한 사례를 찾아 달라고 하면 `search_by_photo`를 쓴다. 아카이브 웹 «이미지로 검색»과 같은 비교다.
- 사진은 파일로 서버에 가야 한다. 도구 인자로는 사진을 넘길 수 없다.
  1. 셸이 있고 사진이 파일로 있으면(Claude Code·Cowork 작업 폴더, claude.ai에서 코드 실행이 켜져 있으면 보통 `/mnt/user-data/uploads`): `photo_upload_link`를 부르고 `upload_command`의 `PHOTO_PATH`를 그 파일 경로로 바꿔 실행한다. 답의 `photo_id`를 `search_by_photo`에 넣는다.
  2. 셸이 없거나 올리기가 막히면(네트워크가 dailyarchive.heeai.cloud를 막는 경우 등): `photo_id` 없이 `search_by_photo`를 부르고 카드 화면의 «사진 고르기» 칸에 사진을 끌어 놓거나 붙여 넣어 달라고 안내한다. 채팅에 붙인 사진도 그 칸에 한 번 더 놓아야 한다. 결과는 카드 화면에 바로 뜬다.
- 사진을 글로 묘사해 `search_cases`로 찾은 결과를 사진 검색이라고 하지 않는다. 두 길이 다 안 되면 그렇다고 말하고, 사진에서 보이는 것으로 글 검색을 할지 묻는다.
- «형태(매스)까지» 비교하려면 `mass: true`를 준다. 1분쯤 걸릴 수 있다(`status: searching`이면 같은 요청을 다시 부른다). 아카이브의 형태 분석이 끝내 안 되면 외관 결과가 `mass_failed`와 함께 온다. 그때는 외관만으로 찾은 결과라고 밝힌다.
- `similarity`는 외관 유사도(0~1)다. 숫자를 늘어놓지 말고 순서와 비슷한 점을 짧게 말한다.
- 올린 사진은 검색에만 쓰이고 1시간 뒤 지워진다.

## 4. 링크·출처
- 사례를 말할 때마다 그 사례의 `archdaily_url`(ArchDaily 원문)을 붙인다. 이름만 쓰고 링크를 빼지 않는다.
- 사진의 저작권은 원 사진가에게 있다(ArchDaily에서 가져옴, 사내 참고용). 밖으로 낼 자료에 쓰겠다고 하면 원문에서 출처와 사용 조건을 확인하라고 말한다.
- `summary`는 아카이브가 원문을 읽고 쓴 한국어 요약이다. 원문 기사를 통째로 옮기지 않는다.
- 아카이브 화면으로 보내는 링크: 같은 검색은 `archive_url`, 비슷한 사례는 `archive_similar_url`.

## 5. 북마크·컬렉션
- `save_case`: 기본은 북마크다. `collection`에 이름을 주면 그 컬렉션에 담고, 그런 컬렉션이 없으면 새로 만든다. `remove: true`면 뺀다. 아카이브 화면의 내 목록과 같은 곳에 저장된다.
- `my_saved_cases`: 북마크와 컬렉션 목록, `collection`을 주면 그 컬렉션의 사례를 본다. `sheet_url`은 아카이브의 인쇄용 레퍼런스 시트 링크다(희림 아이디로 로그인한 브라우저에서 열린다).
- 사용자가 담아 달라고 할 때만 담는다. 검색 결과를 마음대로 담지 않는다.

## 6. 주의
- 도구 오류 메시지에 고칠 방법이 같이 오면 그걸 보고 한 번 다시 시도한다.
- «요청이 너무 잦습니다»는 아이디별 한도(검색 분당 20번, 사진 올리기 분당 10번)다. 잠시 뒤에 다시 부른다.
